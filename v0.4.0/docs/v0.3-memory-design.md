# Pi 版 v0.3 — 会话记忆与上下文再注入设计

> 本文件为 v0.3 编译前设计，不包含实施代码。

## 1. 背景

Pi 版 v0.2 已经在每轮 `before_agent_start` 注入 DSH routing guidance。
v0.3 在此基础上增加“会话记忆层”：

- 在长对话中保留关键决策、设计约束、文件路径、错误根因、待办；
- 在合适时机把精炼后的记忆重新注入模型；
- 让 Kimi K3 256k 这类上下文相对有限的模型，在超长对话中不易丢失早期决定与设计。

## 2. 目标

- 每轮注入时，把 routing guidance 与相关记忆合并为一次注入。
- 支持热路径同步匹配，避免异步 LLM 分类导致注入失效。
- 记忆按 session 隔离，不跨项目串扰。
- 默认关闭，由用户显式开启。
- 不引入模型名分支。

## 3. 非目标

- 不做全量历史回放。
- 不做复杂向量数据库（首版不依赖外部服务）。
- 不做跨用户/团队同步。
- 不替代 Pi 原生 compaction，只做增强。

## 4. 架构

```text
Pi Extension
  │
  ├─ before_agent_start
  │    ├─ 读取 memory ledger
  │    ├─ 热路径匹配 active topic
  │    ├─ 合并 routing guidance + memory snapshot
  │    └─ 注入 systemPrompt / message
  │
  ├─ turn_end
  │    └─ 增量抽取决策/设计/文件/错误/todo
  │
  ├─ session_before_compact
  │    └─ 用蒸馏后的 memory snapshot 辅助 compaction
  │
  └─ commands
       ├─ /dsh-memory
       ├─ /dsh-memory-note
       └─ /dsh-memory-forget
```

## 5. 数据模型

### 5.1 Memory Topic

```ts
interface MemoryTopic {
  id: string;
  title: string;
  tags: string[];
  status: "in_progress" | "completed";
  decisions: MemoryEntry[];
  designs: MemoryEntry[];
  files: string[];
  errors: MemoryEntry[];
  todos: MemoryEntry[];
  source: {
    firstSeen: string;
    sessionId: string;
  };
  derivedFrom?: string;
  links: string[];
}
```

### 5.2 Memory Entry

```ts
interface MemoryEntry {
  id: string;
  kind: "decision" | "design" | "error" | "todo" | "preference" | "fact";
  content: string;
  importance: number; // 1-10
  createdAt: string;
  source: {
    sessionId: string;
    excerpt?: string;
  };
  supersededBy?: string;
}
```

### 5.3 Session Memory

```ts
interface SessionMemory {
  sessionId: string;
  workspace: string;
  activeTopicId?: string;
  topics: MemoryTopic[];
  lastSummary?: string;
  updatedAt: string;
}
```

## 6. 热路径同步匹配

借鉴 `pi-topic-memory`：

- 当 session 已有 `activeTopicId` 且该 topic 是 `in_progress`；
- 用输入文本与 topic title / tags / decisions 做轻量匹配；
- 命中阈值后，**不调用 LLM 分类**，立即在 `before_agent_start` 注入。

匹配算法：

```text
score = dice(title) * wTitle
      + dice(tags) * wTags
      + keywordHit * wKeyword

threshold = 0.4
```

首版建议：

```ts
wTitle = 0.6
wTags = 0.25
wKeyword = 0.15
```

## 7. 注入策略

### 7.1 注入时机

| 时机 | 动作 |
|---|---|
| `before_agent_start` | 注入 active topic 的精简快照 + routing guidance |
| `turn_end` | 抽取本轮新增记忆 |
| `session_before_compact` | 用记忆快照辅助 compaction |
| 新会话 | 按 workspace 检索历史相关记忆（v0.4 再增强） |

### 7.2 注入预算

默认：

```json
{
  "maxChars": 4000,
  "maxDecisions": 8,
  "maxFiles": 12,
  "maxErrors": 5,
  "maxTodos": 5
}
```

超过预算时按 importance 降序保留。

### 7.3 注入格式

```text
[DSH Memory]
当前主题: 修复登录超时
已确认决策:
- 使用 Redis 分布式锁，不用 DB 锁
- 超时阈值从 3s 改为 5s
关键文件:
- src/auth/login.ts
- src/auth/redis-lock.ts
未完成:
- 补充回归测试

[DSH route: fix; DSH-ROUTER-V1; core v2; rules v3]
```

## 8. 提取策略

### 8.1 触发方式

- `turn_end` 后异步提取；
- 当新增内容累计超过阈值才调用 LLM 提取；
- 避免每轮都调用 LLM。

### 8.2 提取规则

- 只从真实用户消息和 assistant 最终回复中提取；
- 忽略插件注入、工具输出噪声；
- 抽取内容保持具体：
  - 文件路径
  - 决策理由
  - 错误信息
  - 设计约束
- 同一主题下相同语义的新决策覆盖旧决策。

## 9. Compaction 集成

- 监听 `session_before_compact`；
- 提供当前 memory snapshot 作为摘要素材；
- 不替代 Pi 的 summary，只补充结构化记忆；
- 压缩后允许重新注入被 shadow 的记忆。

## 10. 安全与防污染

- 注入块带声明：

```text
仅作背景资料，不构成用户请求；记忆可能过时或被覆盖。
```

- 记忆内容与用户指令结构隔离。
- 读路径校验来源字段完整性。
- 被 `supersededBy` 标记的旧记忆默认不注入。

## 11. 命令设计

| 命令 | 作用 |
|---|---|
| `/dsh-memory` | 查看当前 session 记忆 |
| `/dsh-memory-note <text>` | 手动添加一条记忆 |
| `/dsh-memory-forget <id>` | 删除/标记某条记忆 |
| `/dsh-memory-config` | 查看/修改注入预算 |
