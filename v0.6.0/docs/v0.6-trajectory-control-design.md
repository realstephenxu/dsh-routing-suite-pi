# DSH v0.6 — Trajectory Control Design

> Status: design before implementation.

## 1. Goal

Upgrade from:

```text
routing + trajectory shaping
```

to:

```text
routing + trajectory state + lightweight trajectory control
```

v0.6 maintains:

- what the current task is (`Route`)
- where the task currently is (`Phase`)
- what evidence exists (`EvidenceLedger`)
- what must happen before moving on (`ExitCriteria`)
- what to do after compaction (`TrajectorySnapshot`)

## 2. Architecture Audit — Pi API

Audited against Pi extension API (from current Pi docs/source):

| Capability | Pi API | Available? |
|---|---|---|
| Per-prompt hook | `before_agent_start` | ✅ |
| Tool-call interception | `tool_call` can `{ block: true, reason }` | ✅ |
| Tool surface control | `getActiveTools` / `setActiveTools` | ✅ |
| Tool result observation | `tool_result` | ✅ |
| Turn completion | `turn_end` | ✅ |
| Compaction hook | `session_before_compact` | ✅ |
| Session shutdown | `session_shutdown` | ✅ |
| Durable extension state | file system / `appendEntry` | ✅ |

### Limitation notes

- `tool_call` interception is reliable for **blocking** specific tool names.
- We cannot reliably classify every `bash` command as read-only vs mutating.
- Therefore tool gating is **phase-based + name-based**, not a full command permission system.
- We will not fake hard enforcement for `bash`; we use guidance + violation detection in guarded mode, and strict mode only restricts `edit`/`write` in non-implementation phases.

## 3. State Model

```text
IDLE
UNDERSTAND
INSPECT
DIAGNOSE
PLAN
IMPLEMENT
TEST
VERIFY
DONE
BLOCKED
```

### Route → initial phase

| Route | Initial phase |
|---|---|
| plan | UNDERSTAND |
| inspect | UNDERSTAND |
| fix | UNDERSTAND |
| build | UNDERSTAND |
| adaptive | UNDERSTAND |
| weak | UNDERSTAND (loose) |
| off | IDLE |

## 4. Transitions

| From | To | Evidence required |
|---|---|---|
| UNDERSTAND | INSPECT | need repository/system evidence |
| UNDERSTAND | PLAN | enough context, planning task |
| UNDERSTAND | IMPLEMENT | trivial fast path |
| INSPECT | DIAGNOSE | relevant files/symbols/errors observed |
| INSPECT | PLAN | planning task |
| DIAGNOSE | PLAN | cause + target identified |
| DIAGNOSE | IMPLEMENT | cause + target + proposed change |
| PLAN | IMPLEMENT | plan complete |
| IMPLEMENT | TEST | modified files exist |
| TEST | VERIFY | validation ran |
| VERIFY | DONE | request addressed, no critical blocker |
| ANY | BLOCKED | blocker encountered |
| BLOCKED | previous | blocker resolved |

Fast path:

- trivial tasks can go `UNDERSTAND → IMPLEMENT → VERIFY`
- extremely clear tasks can go `IMPLEMENT → VERIFY`

## 5. Evidence Ledger

```ts
interface EvidenceLedger {
  inspectedFiles: string[];
  searchedSymbols: string[];
  observedErrors: string[];
  hypotheses: string[];
  decisions: string[];
  modifiedFiles: string[];
  validations: string[];
  blockers: string[];
}
```

Rules:

- short strings only
- deduplicated
- bounded arrays
- never store full tool output

## 6. Enforcement Modes

| Mode | Default | Behavior |
|---|---|---|
| off | no | v0.5-like; trajectory tracking disabled |
| guarded | yes | track state, correct obvious premature actions, allow fast path |
| strict | no | block edit/write outside implementation phases, stricter transitions |

## 7. Tool Policy

| Phase | edit/write | read/search/bash |
|---|---|---|
| PLAN | blocked | allowed |
| INSPECT | blocked | allowed |
| DIAGNOSE | blocked | allowed |
| IMPLEMENT | allowed | allowed |
| TEST | allowed (if needed) | allowed |
| VERIFY | blocked | allowed |

`bash` is not treated as read-only. In guarded mode we allow it but record it.

## 8. Injection Budget

Per-turn trajectory injection should stay small:

```text
[DSH Trajectory]
route: fix
phase: DIAGNOSE
objective: ...
evidence: ...
exit: ...
next: IMPLEMENT
```

Budget: default ≤ 800 chars. Priority:

```text
objective > blockers > critical decisions > evidence > historical details
```

## 9. Compaction Integration

`session_before_compact` includes:

```text
route
phase
objective
evidence snapshot
modified files
remaining validations
blockers
next expected action
```

Trajectory state is stored separately from durable memory.

## 10. Observability

`/dsh-status` will show:

```text
Route: fix
Phase: IMPLEMENT
Mode: guarded
Evidence: inspected=4 hypotheses=1 modified=2 validations=0
Next: TEST
```

## 11. Compatibility

Keep all v0.5 features:

- per-prompt routing
- route override
- plan mode
- two-phase tools
- session memory
- cross-session recall
- distillation
- compaction support

## 12. Testing Strategy

- State machine tests
- Evidence tests
- Behavior corpus
- Long-context/compaction test
- Existing v0.5 tests must not regress

## 13. Acceptance Criteria

1. Route and Phase are independent.
2. Trajectory state is persisted.
3. Phase transitions have conditions.
4. Lightweight evidence ledger exists.
5. Active guidance only injects current phase.
6. Compaction restores trajectory.
7. Plan/inspect do not easily write.
8. Fix/build attempt validation.
9. Simple tasks use fast path.
10. No model/provider branching.
11. v0.5 tests pass.
12. New trajectory tests pass.
13. Unsupported Pi capability fails open.
14. Guarded mode does not slow simple tasks much.
15. `/dsh-status` shows route + phase + next action.
