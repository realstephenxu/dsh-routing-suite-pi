# Pi 版 v0.5 — 记忆蒸馏与 Compaction 优化设计

> 本文件为 v0.5 设计，基于 v0.4 跨会话记忆。

## 1. 研究参考

- `pi-async-compaction`：后台预计算 compaction summary，避免同步卡顿。
- `pi-agentic-compaction`：让 summarizer 通过工具探索会话，而不是单次全量摘要。
- `EchoCore`：双通道提取、压缩遮蔽时提取、后台整理、去重/覆盖。
- `Lore`：蒸馏优于摘要，保留文件路径、错误信息、决策。

## 2. 目标

- 在 v0.4 基础上增强记忆蒸馏。
- 压缩时提供比简单 summary 更结构化的记忆快照。
- 后台整理重复/过期/被覆盖记忆。
- 不引入外部模型依赖，先用规则蒸馏。

## 3. 非目标

- 不做真正异步后台任务（Pi 扩展能力有限，先用同步轻量整理）。
- 不做 agentic compaction 的虚拟文件系统。
- 不接入外部 embedding。

## 4. 架构

```text
MemoryStore
  ├─ distillTopic(topic): 合并重复、移除 superseded、生成 lastSummary
  ├─ distillSession(session): 对 active topic 调用 distillTopic
  └─ buildCompactionSummary(session): memorySnapshot + lastSummary

session_before_compact
  └─ 返回 buildCompactionSummary 作为 compaction summary

session_shutdown
  └─ 后台整理（同步轻量）
```

## 5. 蒸馏规则

- 相同 normalized content 的 entry 只保留最新一条。
- `supersededBy` 标记的旧 entry 不进入快照。
- 同一 topic 内 decisions 超过 8 条时，按 importance + recency 截断。
- 生成 `lastSummary`：

```text
主题: <title>
决策: <前3条>
设计: <前2条>
错误: <前2条>
待办: <前2条>
```

## 6. Compaction Summary

`session_before_compact` 返回：

```json
{
  "compaction": {
    "summary": "主题... 决策... 设计...",
    "firstKeptEntryId": "...",
    "tokensBefore": 12345
  }
}
```

## 7. 命令

| 命令 | 作用 |
|---|---|
| `/dsh-memory-distill` | 立即蒸馏当前 session 记忆 |
| `/dsh-memory-summary` | 显示当前蒸馏摘要 |
